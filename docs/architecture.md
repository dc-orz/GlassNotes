# 原生桌面便签技术方案

## 系统与构建

目标为本机使用的 macOS 14+ 菜单栏应用。Swift Package Manager 构建三个 Swift 模块，AppKit 管理桌面窗口、状态栏、快捷键和弹出面板，SwiftUI 承载视图。仓库使用 macOS 26 或更新的 SDK 和 Swift 6.2+ 编译。应用运行时按系统版本选择玻璃实现。

## 从输入到窗口

菜单栏输入和原位编辑共用同一份便签状态。每张未完成便签拥有独立 NSPanel，位于桌面图标层上方、普通应用窗口下方。查看时，NotePanel 将右下角操作区以外的鼠标主键按下事件交给系统拖窗。操作区使用按钮行的实际布局边界。滚轮和键盘事件走原生分发。右下角铅笔进入编辑态，正文支持定位光标和拖选文字，确认后保存，Esc 取消。窗口坐标按所在显示器可用区域的比例保存，以显示器 UUID 标识。显示器离线时临时映射到主屏，用户主动移动时再更新归属。

完成操作先记录完成时间。桌面视图收到新状态后擦去墨迹并淡出玻璃。撤销清除完成时间并恢复原位置。归档项保留正文和坐标。菜单栏面板提供独立于桌面动画的恢复入口。

## 持久化

首版本机单进程写入一份有版本号的 JSON 文档。选择它是因为数据只有便签和位置，容易备份，也能用临时目录验证故障恢复。文件只在用户操作时原子替换；写入成功后才改变内存快照。持有进程锁防止多实例写入。遇到损坏文件或更新版本时停止写入并告知用户。首次创建存档时放入四张可编辑示例，之后以存档为准。若增加 WidgetKit 或云同步，先重新设计跨进程写入与合并，再接入同一业务入口。

## 设计系统

NoteDesign/Tokens.swift 为运行时样式的唯一来源。模块内的玻璃组件在 macOS 26+ 调用系统 Liquid Glass，14–15 使用 NSVisualEffectView 的 behindWindow 混合。减少透明度时使用实色。桌面窗口和菜单通过 DesktopGlassPreference 订阅同一项 AppStorage 偏好。预设仍按原有字符串保存，自定义值在同一偏好键中一次写入基础预设、材质不透明度及压暗值。拖动滑块或恢复预设后，已打开的窗口就地刷新玻璃层，新建和恢复的窗口读取当前值。透明度独立于便签存档。存档 v1 中的 ink 字段仅作旧版读写兼容，原值在编辑时保留，新记录使用 chalk。桌面不采集屏幕内容。

标题和正文通过 SwiftUI 系统字体 API 渲染，按语言和字形覆盖回退。字体文件由 macOS 提供。标题使用中等字重，正文使用常规字重。完成时从左至右擦字 180 ms，再淡出玻璃 120 ms；减少动态效果时整张淡出 80 ms。撤销浮条保留 5 秒，之后仍可从已完成列表恢复。

参考 [Apple 自定义 Liquid Glass](https://developer.apple.com/documentation/swiftui/applying-liquid-glass-to-custom-views) 和 [Apple 应用字体指南](https://developer.apple.com/documentation/technologyoverviews/managing-the-fonts-for-your-app)。
